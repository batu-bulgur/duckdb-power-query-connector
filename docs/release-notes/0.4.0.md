# 0.4.0 — Scalar parity and ordered index folding

This personal-fork release expands the first 14 parity targets while retaining
the existing ODBC source and public `DuckDB.Contents` signature. It does not
claim complete M-language parity or support for every composition.

## Added

- A relational SQL plan for projection, filtering, sorting, take/skip, grouping,
  distinct, calculated columns and `Table.AddIndexColumn`. Index plans preserve
  operation order and use sequential floating-point addition when a direct
  arithmetic index would disagree with M.
- Wider mappings for `Text.EndsWith`, `Text.Length`, `Text.Middle`, `Text.Range`,
  `Text.PositionOf`, `Text.PadStart`, `Text.PadEnd`, `Text.Trim`, `Text.TrimStart`
  and `Text.TrimEnd`, including UTF-16 units, dynamic arguments and supported
  Ordinal/OrdinalIgnoreCase comparisons.
- `Number.Round` mappings for all five modes with numeric representation and
  decimal/binary precision controls, plus type-aware `Value.Equals` and
  `Value.NullableEquals` over the documented primitive and known-list domains.
- SQL value/error transport and reconstruction of normal M error records,
  including predicate errors across supported table operations.
- A dated 705-entry M inventory, 67 research candidates, source-free M references,
  buffered differential oracles and executable SDK boundary probes.
- Bounded parallel verification of the same immutable artifact. Four exhaustive,
  disjoint folding partitions retain all correct-result, SQL and ODBC-row guards.

## Fixed

- Integration retains the sample-standard-deviation aggregate mapping and all
  previous fork regressions alongside the expanded scalar visitor.
- The versioning checks and package/source guards remain part of local and
  hosted verification; the expanded suite receives sufficient CI time and
  retained evidence.

## Query folding

The suite checks 101 new parity cases, all 40 existing folding cases and one
index/standard-deviation integration case. The parity cases include 24
ordered-index cases. Each folding case must
match its committed output, execute one successful ODBC query, contain the
required SQL algorithm and stay within its transfer budget. Buffered oracles
separately compare the SQL calculation with a deliberately local M reference.

The previously released pagination, text/Unicode filtering and sample standard
deviation remain covered. See [the measured scope](../scalar-parity.md) and
[per-function status](../m-parity/first14-status.csv) for overload/domain limits.

## Known limitations

- Row-dependent list/record constructors are not exposed by the pinned public
  expression hook. Culture/custom comparer closures do not expose sufficient
  serializable context. Both have executable negative controls.
- Two native SDK CLR failure families in Round and Middle do not produce normal
  catchable M error records. The SQL guards and separate native reproducers do
  not establish identical exception behavior.
- Arbitrary joins, pivot/unpivot, unsupported surrounding expressions and
  downstream transformations after `Value.NativeQuery` remain outside the
  implemented plan. Unsupported cases must not be reported as folded.
- OrdinalIgnoreCase mappings are measured against SDK 2.155.2 on Windows;
  other Mashup/NLS versions require validation. Recursive fractional-index plans
  preserve semantics but are not a general performance guarantee.
- Excel and Power BI Desktop GUI integration remain separate host checks. No
  installed driver, DSN, trust/security setting or user app session is changed.

## Validation

Final local verification runs the functional and differential suites, 100
source-free M references, 142 strict folding cases, 3 negative controls, 2 native
failure reproducers, and runner/version/package rejection checks. All 18
allowlisted package resources must match current source. Tests never regenerate
baselines. The local measured ODBC engine is 1.5.4; hosted CI independently uses
the pinned 1.4.4 driver and the same SDK 2.155.2.

Publication requires successful CI for the exact main commit and reuses its
MSBuild artifact. The release manifest records the commit, source build URL,
toolchain versions and downloadable `.mez` SHA-256. SDK evidence does not imply
GUI validation or full M-language parity.
