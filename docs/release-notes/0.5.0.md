# 0.5.0 — GUI date calculations

## Added

- The next eight GUI-oriented inventory targets: `Date.Year`, `Date.Month`,
  `Date.Day`, `Date.DayOfWeek`, `Date.AddDays`, `Date.AddMonths`,
  `Date.StartOfMonth` and `Date.EndOfMonth`.
- Dynamic arguments, nullable results, month-end clipping, host-captured default
  weekday behavior, same-kind date conditionals and normal M error records.

## Fixed

- Owned SQL views avoid a native shadow base that interrupted strict folding
  when an index followed a calculated date/filter/sort chain.
- Operands mirror M's native ODBC BOOLEAN/TIME/TIMESTAMP_NS conversion. The old
  time-equality fixture assumed a fractional TIME value survived the driver;
  its expectation is corrected using buffered M evidence.
- Timestamp conversion is calibrated from fixed values actually read by M in
  the existing bounded catalog request. This handles the hosted ODBC 1.4.4
  fraction-field scale difference without a version guess or driver changes.

## Query folding

- SQL calculations retain M's temporal result kind, seventh fractional digit
  and explicit datetimezone offset across the ODBC boundary.
- Twenty new strict date cases include a million-row filter transferring three
  rows, 100 ns comparisons, explicit-zone instant equality, index/group/distinct
  chains and GUI-style column transformation. Timestamp inputs use one bounded
  physical-type catalog request where required, checked separately from the
  single data calculation and its row budget.

## Known limitations

- Native SQL TIMESTAMPTZ still uses M: the ODBC schema hides its physical kind,
  and Windows/M versus IANA/server historical local-clock rules can disagree.
  A catalog classification guard prevents a different server result from being
  claimed as successful folding. Full host-rule serialization remains required.
- Two date UTC-offset range failures crash the native SDK despite M `try`.
  Separate native reproducers and SQL guards preserve this boundary.
- Existing opaque comparer/AST-constructor boundaries, untranslated surrounding
  expressions and host GUI validation remain open. Complete M parity is not claimed.
- Details and executable evidence are in the
  [date parity report](https://github.com/batu-bulgur/duckdb-power-query-connector/blob/fork-v0.5.0/docs/date-parity.md).

## Validation

- Local full verification passed with SDK 2.155.2 and ODBC engine v1.5.4:
  36 functional cases, 189,372 direct M comparisons, 108 M references,
  162 strict SQL/ODBC folding cases, four negatives, four native failure
  reproducers and 16 evidence-runner rejection controls. Package/source hashes
  match all 19 allowlisted resources. Of these, 141,434 direct comparisons and
  20 folding cases cover the new date/input behavior.
- Hosted CI uses the separately pinned ODBC 1.4.4.0. SDK/ODBC verification does
  not establish Excel or Power BI Desktop GUI integration.
